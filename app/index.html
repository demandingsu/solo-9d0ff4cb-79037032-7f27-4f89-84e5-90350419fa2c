市政工程投标公告采集 API

接口

  • POST /api/collect — 传入 {"catalog_url": "..."} 触发采集，成功后整体替换旧结果，失败保留旧结果
  • GET /api/tenders — 各标段当前投标截止时间汇总（冲突标段 status=conflict）
  • GET /api/tenders/{招标编号} — 单标段有效公告链、失效原因与来源链接
  • POST /api/crosscheck — 双来源一致性核对：传入两个招标网站的目录 URL，按公告编号+招标编号配对并形成版本链，输出一致/单方缺失/内容冲突/无法判定，含冲突字段与双方来源链接
  • GET /api/raw — 最近一次采集的原始公告数据
  • GET /docs — Swagger 交互文档
  • 离线样例站点 A（/sample，纯静态无外部依赖）
  • 离线样例站点 B（/sample-b，双来源核对专用，含冲突与单方缺失场景）

典型流程

  1. 打开 样例目录 A 与 样例目录 B，分别复制目录第一页 URL
  2. 调用 POST /api/crosscheck，请求体： {"source_a": ".../sample/catalog/page_1.html", "source_b": ".../sample-b/catalog/page_1.html"}
  3. 按 tenders[].pairs[] 核对配对状态；needs_verification=true 表示受采集失败影响需人工核实，field_conflicts 给出冲突字段与双方取值
  4. 单站采集场景仍可调用 POST /api/collect，再通过 GET /api/tenders 核对截止时间
